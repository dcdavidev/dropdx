# Architecture

This guide describes the layout, configuration conventions, build pipeline, and developer toolchain of dropdx.

## Overview

dropdx is a single-package TypeScript and ECMAScript Module (`"type": "module"`) CLI and library for automated releases and npm publishing. It is built on the [spellbookx-template-singlerepo](https://github.com/dcdavidev/spellbookx-template-singlerepo) layout and the Spellbookx developer toolchain:

- **Runtime & package manager**: Node.js `26.x` (pinned in [`.nvmrc`](../../.nvmrc)) and pnpm `12.x` (pinned via `packageManager` in [`package.json`](../../package.json)).
- **Language & compiler**: TypeScript targeting `ES2024` with `NodeNext` module resolution and strict type-checking.
- **Task orchestration**: [Turborepo](https://turborepo.com/) for local task caching and parallel execution (`pnpm check`, `pnpm lint`).
- **Quality & formatting**: ESLint (`eslint-plugin-spellbookx`), Prettier (`prettier-config-spellbookx`), CSpell (`cspell-config-spellbookx`), Commitlint (`commitlint-config-spellbookx`), `czg` (`cz-config-spellbookx`), and Lefthook.
- **Testing & releases**: [Vitest](https://vitest.dev/) with V8 coverage and [Changesets](https://github.com/changesets/changesets).

## Configuration Placement Convention

Configuration files follow a consistent placement rule:

- **Files with `.config.` in the name** live in the **repository root**, where their CLIs discover them automatically without extra flags: [`eslint.config.mjs`](../../eslint.config.mjs), [`prettier.config.mjs`](../../prettier.config.mjs), [`commitlint.config.mjs`](../../commitlint.config.mjs), and [`cz.config.mjs`](../../cz.config.mjs).
- **Tool-name-only configuration files** live in `.config/`: [`.config/cspell.yml`](../../.config/cspell.yml) (with its dictionary at [`.config/cspell/custom.txt`](../../.config/cspell/custom.txt)) and [`.config/lefthook.yml`](../../.config/lefthook.yml). Both CSpell and Lefthook auto-discover their files inside `.config/`.
- **Core platform files** stay in the repository root as required by their tools: [`package.json`](../../package.json), [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml), [`tsconfig.json`](../../tsconfig.json), [`tsconfig.build.json`](../../tsconfig.build.json), [`turbo.json`](../../turbo.json), [`.nvmrc`](../../.nvmrc), [`.editorconfig`](../../.editorconfig), and [`.prettierignore`](../../.prettierignore).

## Build and Package Exports

The project separates type-checking from build emission using two TypeScript configurations:

- [`tsconfig.json`](../../tsconfig.json) sets `noEmit: true` and covers `src/**/*`, `tests/**/*`, and `scripts/**/*`. It is used by `pnpm lint:types` (`tsc --noEmit`) and editor language services.
- [`tsconfig.build.json`](../../tsconfig.build.json) extends `tsconfig.json`, sets `noEmit: false`, restricts `include` to `src/**/*`, and emits JavaScript, `.d.ts` type declarations, `.d.ts.map` declaration maps, and `.js.map` source maps into `dist/`. It is used by `pnpm build` (`tsc -p tsconfig.build.json`).

In [`package.json`](../../package.json), `bin` and `dist` are listed in `files`. The package exposes the `dropdx` command via `bin` and the programmatic API via `exports`, `main`, `module`, and `types`:

```json
{
  "exports": {
    "./package.json": "./package.json",
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "default": "./dist/index.js"
    }
  },
  "bin": {
    "dropdx": "bin/dropdx.js"
  }
}
```

[`bin/dropdx.js`](../../bin/dropdx.js) is a thin launcher that imports the compiled CLI from `dist/`, so run `pnpm build` before trying the CLI locally. The `prepack` script builds automatically before `pnpm pack` and `pnpm publish`.

## Source Layout

- [`src/cli.ts`](../../src/cli.ts): CLI entry point and the 7-step release pipeline.
- [`src/config.ts`](../../src/config.ts): CLI argument parsing and `.config/dropdx.config.*` loading.
- [`src/init.ts`](../../src/init.ts): the `dropdx init` command.
- [`src/engines/`](../../src/engines/): release engine detection and adapters (Changesets, release-it, semantic-release, Lerna, bumpp, standard-version, np, and the built-in engine).
- [`src/utils/`](../../src/utils/): shared helpers for git, `.npmrc`, the registry, SemVer, package discovery, changelogs, and process execution.
- [`src/index.ts`](../../src/index.ts): public programmatic API.

dropdx releases itself: `pnpm release` builds the package and runs `bin/dropdx.js` with the repository config in [`.config/dropdx.config.json`](../../.config/dropdx.config.json).

## Quality Toolchain and Git Hooks

All linting, formatting, spelling, and commit rules come from Spellbookx preset packages:

| Concern           | Config file                                            | Preset package                                                 |
| :---------------- | :----------------------------------------------------- | :------------------------------------------------------------- |
| Code linting      | [`eslint.config.mjs`](../../eslint.config.mjs)         | `eslint-plugin-spellbookx` (`recommended-spellcheck` + `node`) |
| Formatting        | [`prettier.config.mjs`](../../prettier.config.mjs)     | `prettier-config-spellbookx/base`                              |
| Spell-checking    | [`.config/cspell.yml`](../../.config/cspell.yml)       | `cspell-config-spellbookx`                                     |
| Commit validation | [`commitlint.config.mjs`](../../commitlint.config.mjs) | `commitlint-config-spellbookx`                                 |
| Guided commits    | [`cz.config.mjs`](../../cz.config.mjs)                 | `cz-config-spellbookx`                                         |
| Git hooks         | [`.config/lefthook.yml`](../../.config/lefthook.yml)   | `lefthook`                                                     |

[`.config/lefthook.yml`](../../.config/lefthook.yml) defines two hooks installed by `pnpm prepare`:

- **`pre-commit`** (piped): runs `eslint --no-warn-ignored --fix` and then `prettier --ignore-unknown --write` on staged files, automatically re-staging any fixes (`stage_fixed: true`).
- **`commit-msg`**: validates the commit message with `commitlint --edit {1}`.

## Task Caching (Turborepo)

Even in a single-package repository, [`turbo.json`](../../turbo.json) caches local verification tasks so unchanged inputs finish immediately:

- **Global dependencies**: `.nvmrc` and `pnpm-lock.yaml` invalidate cached results whenever the Node.js version or installed dependencies change.
- **Cached tasks**: `build` (outputs `dist/**`), `lint:code`, `lint:spelling`, `lint:types`, `fmt:check`, and `test` (outputs `coverage/**`).
- **Aggregate commands**: `pnpm lint` runs `lint:code` and `lint:spelling`; `pnpm check` runs all six tasks in parallel. Pass `--force` to bypass the local `.turbo/` cache.

## pnpm Workspace Settings

[`pnpm-workspace.yaml`](../../pnpm-workspace.yaml) configures single-repo pnpm policies:

- `allowBuilds`: explicitly permits post-install build scripts only for `esbuild` and `lefthook`.
- `engineStrict: true`: enforces runtime and package manager constraints.
- `publicHoistPattern`: hoists `*prettier-plugin-*` and `@prettier/plugin-*` so Prettier and editor plugins resolve Spellbookx's bundled Prettier plugins cleanly.

## CI and Maintenance Automation

- **CI** ([`.github/workflows/code-quality-tests-build.yml`](../../.github/workflows/code-quality-tests-build.yml)): runs on every pull request and push to `main` with `LEFTHOOK=0` and `TURBO_TELEMETRY_DISABLED=1`, executing install, build, PR commitlint, lint, format check, spell check, type check, and tests as separate steps.
- **Maintenance scripts**: [`scripts/update-node.ts`](../../scripts/update-node.ts) and [`scripts/update-turbo.ts`](../../scripts/update-turbo.ts) are run via `tsx` both locally (`pnpm update:node`, `pnpm update:turbo`) and on weekly GitHub Actions schedules ([`update-node.yml`](../../.github/workflows/update-node.yml) and [`update-turbo.yml`](../../.github/workflows/update-turbo.yml)) that open automated pull requests when updates are available.
- **Dependency updates**: [`.github/dependabot.yml`](../../.github/dependabot.yml) schedules weekly grouped updates for npm dependencies and GitHub Actions.
